# ДЗ 4. Координатор расчёта из ДЗ 3 под Apache ZooKeeper

Расчёт частот сочетаний навыков для вакансий DevOps-инженера. Ансамбль из трёх ZooKeeper 3.9.6 в Docker, две копии координатора MapReduce с тайм-аутом сессии 10 секунд, пауза лидера посреди расчёта, продолжение с чекпоинта на запасном координаторе и защита публикации по эпохе.

Отчёт: [report.pdf](report/report.pdf). Команды и результаты проверки ансамбля: [stage2-results.md](report/stage2-results.md).

## Что внутри

```text
compose.yaml              три сервера ZooKeeper и отдельные тома данных
src/
  coordinator.py          выбор лидера и расчёт с восстановлением чекпоинтов
  checkpoint.py           сохранение и загрузка результатов частей расчёта
  publisher.py            публикация указателя с защитой по эпохе и без неё
  mapreduce_v2.py         расчёт частот сочетаний навыков из ДЗ 3
  common.py               работа с данными и S3-совместимым хранилищем
  pause_process.py        приостановка и возобновление процесса координатора
scripts/
  run_unfenced_demo.ps1   эксперимент без защиты
  run_fenced_demo.ps1     эксперимент с защитой по эпохе
  pause_leader_when_ready.ps1  ожидание чекпоинта и приостановка лидера
tests/                    модульные тесты защиты и приостановки
data/reference/           эталонные результаты ДЗ 3
data/results_hw4/         результаты координаторов
logs/zk/                  выводы команд проверки ансамбля
logs/hw4/                 журналы координаторов и времени приостановки
report/                   отчёт, результаты проверки ансамбля и скриншоты
```

## Как запустить

Нужны Windows с PowerShell, Docker Desktop, Python и RustFS из ДЗ 3 с бакетом `hh-lake` и исходным объектом `raw/vacancies.csv`. Автоматические сценарии ожидают соседний проект `../ITMO-Data-Engineering` с файлом `compose.yaml` и запущенным сервисом `rustfs-home` на `127.0.0.1:9010`. Учётные данные RustFS считываются из конфигурации контейнера. Для сравнения с эталоном нужен тот же набор данных, что использовался в ДЗ 3.

Из корня репозитория:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
docker compose up -d
docker compose ps
docker compose exec zk1 zkServer.sh status
docker compose exec zk2 zkServer.sh status
docker compose exec zk3 zkServer.sh status
```

Эксперименты запускаются при работающих трёх серверах ZooKeeper и RustFS. Для каждого запуска нужен новый `RunId`: существующие журналы не перезаписываются.

```powershell
$env:FENCING = '0'
.\scripts\run_unfenced_demo.ps1 -RunId unfenced-my-run-01 -PauseSeconds 45
.\scripts\run_fenced_demo.ps1 -RunId fenced-my-run-01 -PauseSeconds 45
```

Скрипты запускают два координатора, ждут первого чекпоинта и приостанавливают лидера. В защищённом сценарии пауза продолжается до завершения резервного координатора, но не менее заданного времени и не более пяти минут. В незащищённом сценарии резервный координатор должен завершить расчёт до возобновления прежнего лидера; при необходимости увеличьте `PauseSeconds` и используйте новый `RunId`. Переменная `FENCING=0` задана явно, чтобы не унаследовать включённую защиту из текущей сессии PowerShell.

Проверка ролей, отказов серверов и эфемерного узла описана в [результатах этапа 2](report/stage2-results.md). Журналы новых запусков сохраняются в `logs/hw4/<RunId>/`, результаты — в `data/results_hw4/<RunId>/`.

## Результаты

- При остановке одного сервера ансамбль продолжает работать и принимает запись; при остановке двух теряется кворум и запись не проходит.
- Эфемерный узел исчезает после закрытия клиентской сессии.
- Без защиты запасной координатор восстановил два чекпоинта и записал результат; возобновившийся лидер записал его второй раз — версия указателя стала 2. Смена лидера заняла 9,915 секунды. [Журналы](logs/hw4/unfenced-20261106-09/).
- С `FENCING=1` запись прежнего лидера отклонена с `BadVersionError`, указатель версии 1 остался от запасного координатора. Смена лидера заняла 10,263 секунды. [Журналы](logs/hw4/fenced-20261109-02/).
- Сохранённые CSV обоих координаторов совпали по SHA-256 с эталоном ДЗ 3: 1 401 навык, 20 454 пары и 144 024 тройки.
